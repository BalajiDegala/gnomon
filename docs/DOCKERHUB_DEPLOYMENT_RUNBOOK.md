# Gnomon deployment runbook (Docker Hub, Helm or plain Kubernetes)

Interim procedure while Harbor and Argo CD are not available. Images are built on a
workstation, pushed to **private Docker Hub repositories**, and deployed to the
single-node `dd-test.d2-india.com` cluster at **http://gnomon.d2-india.com**, using
**one** of:

- **Path A — Helm** chart `deploy/helm/gnomon` with the `values-dockerhub.yaml` overlay.
- **Path B — plain Kubernetes** manifests in `deploy/kubernetes` (`kubectl apply -k`).

Both produce the same application. They use different resource names, so **run only
one at a time** in the `gnomon` namespace (see [Switching paths](#7-switching-between-helm-and-kubectl)).

## Placeholders used below

| Placeholder      | Meaning                                                         |
| ---------------- | --------------------------------------------------------------- |
| `DOCKERHUB_USER` | Docker Hub username that owns the repositories                  |
| `TAG`            | Image tag printed by `scripts/push-dockerhub-images.sh`         |
| `/secure/...`    | A private location outside the repository; never commit secrets |

```sh
export DOCKERHUB_USER=<your-docker-hub-username>
cd /dd/ayon/git/gnomon
```

## What gets deployed

| Component               | Helm name (Path A)             | kubectl name (Path B)   |
| ----------------------- | ------------------------------ | ----------------------- |
| API Deployment/Service  | `gnomon-gnomon-api`            | `gnomon-api`            |
| Web Deployment/Service  | `gnomon-gnomon-web`            | `gnomon-web`            |
| MongoDB StatefulSet/pod | `gnomon-gnomon-mongodb(-0)`    | `gnomon-mongodb(-0)`    |
| Backup CronJob          | `gnomon-gnomon-mongodb-backup` | `gnomon-mongodb-backup` |
| Runtime secret          | `gnomon-runtime`               | `gnomon-secrets`        |
| MongoDB PV (local)      | `gnomon-mongodb`               | `gnomon-k8s-mongodb`    |
| Backup PV (local)       | `gnomon-mongodb-backups`       | `gnomon-k8s-backups`    |
| Ingress                 | `gnomon-gnomon`                | `gnomon`                |

Both PV sets point at the same node directories:
`/pipedev/k8s-local/gnomon-mongodb` (database) and `/pipedev/k8s-local/gnomon-backups`
(nightly `mongodump` archives, kept 14 days). StorageClass `gnomon-local` has no
provisioner: local storage only.

## 1. One-time preparation

### 1.1 Docker access on the build machine

`docker` must work for your user, or the script falls back to `sudo docker`.
To use Docker without sudo (then log out and back in):

```sh
sudo usermod -aG docker "$USER"
```

### 1.2 Docker Hub repositories and access token

1. On hub.docker.com create two **private** repositories: `gnomon-api` and `gnomon-web`.
   The free Docker Personal plan allows only a limited number of private repositories;
   check your plan if creating the second one fails.
2. Account settings → Personal access tokens → create a token with **Read & Write**
   (for pushing). Optionally create a second **Read-only** token for the cluster.
3. Log in on the build machine (paste the token as the password):

   ```sh
   docker login -u "$DOCKERHUB_USER"          # or: sudo docker login ...
   ```

### 1.3 Namespace and image pull secret

```sh
kubectl create namespace gnomon --dry-run=client -o yaml | kubectl apply -f -

kubectl -n gnomon create secret docker-registry dockerhub-registry \
  --docker-server=https://index.docker.io/v1/ \
  --docker-username="$DOCKERHUB_USER" \
  --docker-password='<read-only-access-token>'
```

Both paths reference this secret as `dockerhub-registry`.

### 1.4 Node storage directories

On `dd-test.d2-india.com`:

```sh
sudo mkdir -p /pipedev/k8s-local/gnomon-mongodb /pipedev/k8s-local/gnomon-backups
sudo chmod 0755 /pipedev/k8s-local/gnomon-mongodb /pipedev/k8s-local/gnomon-backups
```

> **Existing data warning.** `/pipedev/k8s-local/gnomon-mongodb` already holds a MongoDB
> data set from an earlier deployment. Its root password was generated by
> `scripts/bootstrap-cicd.py` and lived only in the old `gnomon-runtime` secret, which no
> longer exists. MongoDB applies `MONGO_INITDB_ROOT_PASSWORD` **only to an empty
> directory**, so with a new password the API will fail with "Authentication failed".
> Unless you still have the original password, move the old data aside and start fresh:
>
> ```sh
> sudo mv /pipedev/k8s-local/gnomon-mongodb /pipedev/k8s-local/gnomon-mongodb.old-$(date +%Y%m%d)
> sudo mkdir -p /pipedev/k8s-local/gnomon-mongodb
> ```

### 1.5 Generate secret values

Keep these somewhere private; you need the same values for every later deployment.

```sh
openssl rand -hex 32   # ACCESS_TOKEN_SECRET
openssl rand -hex 32   # REFRESH_TOKEN_SECRET (different value)
openssl rand -hex 32   # SETTINGS_ENCRYPTION_KEY (encrypts the stored SMTP password)
openssl rand -hex 24   # MongoDB root password
```

## 2. Build and push images

Run for every release, from the repository root:

```sh
DOCKERHUB_USER="$DOCKERHUB_USER" scripts/push-dockerhub-images.sh
```

It builds `apps/api` and `apps/web` for linux/amd64, pushes
`docker.io/$DOCKERHUB_USER/gnomon-api:TAG` and `.../gnomon-web:TAG`, and prints the
deploy commands. The default `TAG` is `<package version>-<git short sha>` (plus
`-dirty-<time>` for uncommitted changes), so **every build gets a new tag**. Do not reuse
tags: pods only pull a tag they do not already have.

```sh
export TAG=<tag printed by the script>
```

## 3. Path A — Helm

### 3.1 Storage (once)

```sh
kubectl apply -f deploy/cicd/storage.yaml
```

Creates StorageClass `gnomon-local`, PV `gnomon-mongodb` (20Gi) and PV
`gnomon-mongodb-backups` (50Gi, reserved for the chart's backup claim).

### 3.2 Runtime secret (once)

The MongoDB URI host is the chart's service `gnomon-gnomon-mongodb`.

```sh
MONGO_PASSWORD=<mongodb-root-password>
kubectl -n gnomon create secret generic gnomon-runtime \
  --from-literal=ACCESS_TOKEN_SECRET=<access-token-secret> \
  --from-literal=REFRESH_TOKEN_SECRET=<refresh-token-secret> \
  --from-literal=SETTINGS_ENCRYPTION_KEY=<settings-key> \
  --from-literal=MONGO_INITDB_ROOT_PASSWORD="$MONGO_PASSWORD" \
  --from-literal=MONGODB_URI="mongodb://gnomonadmin:${MONGO_PASSWORD}@gnomon-gnomon-mongodb:27017/gnomon?authSource=admin" \
  --from-literal=ADMIN_EMAIL=<admin-email> \
  --from-literal=ADMIN_PASSWORD=<initial-admin-password> \
  --from-literal=ADMIN_EMPLOYEE_CODE=DDI0001
```

### 3.3 Image settings

Either replace `DOCKERHUB_USER` once in `deploy/helm/gnomon/values-dockerhub.yaml`, or pass
the repositories on every command. The commands below pass them, so the file can stay
generic:

```sh
HELM_IMAGES=(
  --set api.image.repository=docker.io/$DOCKERHUB_USER/gnomon-api
  --set web.image.repository=docker.io/$DOCKERHUB_USER/gnomon-web
  --set adminSeed.image.repository=docker.io/$DOCKERHUB_USER/gnomon-api
  --set-string api.image.tag=$TAG,web.image.tag=$TAG,adminSeed.image.tag=$TAG
)
```

### 3.4 Validate, then first install (with the admin seed)

```sh
helm lint deploy/helm/gnomon -f deploy/helm/gnomon/values-dockerhub.yaml "${HELM_IMAGES[@]}"
helm template gnomon deploy/helm/gnomon -n gnomon \
  -f deploy/helm/gnomon/values-dockerhub.yaml "${HELM_IMAGES[@]}" | kubectl apply --dry-run=server -f -

helm upgrade --install gnomon deploy/helm/gnomon -n gnomon \
  -f deploy/helm/gnomon/values-dockerhub.yaml "${HELM_IMAGES[@]}" \
  --set adminSeed.enabled=true --wait --timeout 10m
```

The admin seed **resets the admin password to `ADMIN_PASSWORD`** every time it runs, so
enable it only on this first install (or deliberately, to recover the admin login).

### 3.5 Upgrade to a new release

After [step 2](#2-build-and-push-images) with the new `TAG`, rebuild `HELM_IMAGES` and run:

```sh
helm upgrade gnomon deploy/helm/gnomon -n gnomon \
  -f deploy/helm/gnomon/values-dockerhub.yaml "${HELM_IMAGES[@]}" --wait --timeout 10m
kubectl -n gnomon rollout status deploy/gnomon-gnomon-api
kubectl -n gnomon rollout status deploy/gnomon-gnomon-web
```

### 3.6 Roll back

```sh
helm history gnomon -n gnomon
helm rollback gnomon <revision> -n gnomon --wait
```

### 3.7 Remove (data is kept)

```sh
helm uninstall gnomon -n gnomon
```

PVs use `Retain`, and the backup claim is annotated `helm.sh/resource-policy: keep`.
Delete `pvc/data-gnomon-gnomon-mongodb-0` only when you intend to give up the volume.

> `deploy/gitops/gnomon-application.yaml.tpl` and the Jenkins pipeline still target Harbor
> and Argo CD; do not use them until those services exist.

## 4. Path B — plain Kubernetes (kubectl)

### 4.1 Runtime secret (once)

The MongoDB URI host is the StatefulSet pod `gnomon-mongodb-0.gnomon-mongodb`.

```sh
MONGO_PASSWORD=<mongodb-root-password>
kubectl -n gnomon create secret generic gnomon-secrets \
  --from-literal=ACCESS_TOKEN_SECRET=<access-token-secret> \
  --from-literal=REFRESH_TOKEN_SECRET=<refresh-token-secret> \
  --from-literal=SETTINGS_ENCRYPTION_KEY=<settings-key> \
  --from-literal=MONGO_INITDB_ROOT_PASSWORD="$MONGO_PASSWORD" \
  --from-literal=MONGODB_URI="mongodb://gnomonadmin:${MONGO_PASSWORD}@gnomon-mongodb-0.gnomon-mongodb:27017/gnomon?authSource=admin" \
  --from-literal=ADMIN_EMAIL=<admin-email> \
  --from-literal=ADMIN_PASSWORD=<initial-admin-password> \
  --from-literal=ADMIN_EMPLOYEE_CODE=DDI0001
```

(`deploy/kubernetes/secret.example.yaml` shows the same keys as YAML.)

### 4.2 Point the manifests at your images

```sh
sed -i -E "s#(newName: docker.io/)[^/]+/#\1$DOCKERHUB_USER/#; s#(newTag: ).*#\1\"$TAG\"#" \
  deploy/kubernetes/kustomization.yaml
kubectl kustomize deploy/kubernetes | grep 'image:'      # check the result
```

Commit this change so the repository records what is deployed.

### 4.3 Validate and apply

Storage (StorageClass + both PVs) is part of the kustomization.

```sh
kubectl apply -k deploy/kubernetes --dry-run=server
kubectl apply -k deploy/kubernetes
kubectl -n gnomon rollout status statefulset/gnomon-mongodb
kubectl -n gnomon rollout status deploy/gnomon-api
kubectl -n gnomon rollout status deploy/gnomon-web
```

### 4.4 First admin (first install only)

Set the image line in `deploy/kubernetes/admin-seed-job.yaml` to
`docker.io/$DOCKERHUB_USER/gnomon-api:$TAG`, then:

```sh
kubectl apply -f deploy/kubernetes/admin-seed-job.yaml
kubectl -n gnomon logs -f job/gnomon-admin-seed
kubectl -n gnomon delete job gnomon-admin-seed
```

Like the Helm seed, it resets the admin password whenever it runs.

### 4.5 Upgrade to a new release

[Step 2](#2-build-and-push-images) with the new `TAG`, then repeat 4.2 and 4.3.

### 4.6 Roll back

Set `newTag` back to the previous tag (step 4.2 with the old `TAG`, or `git revert` the
commit that changed it) and `kubectl apply -k deploy/kubernetes`. Avoid relying on
`kubectl rollout undo`: the next `apply` would restore whatever the kustomization says.

### 4.7 Remove (data is kept)

```sh
kubectl delete -k deploy/kubernetes --ignore-not-found
```

This also deletes the PVs and the **namespace, including the `gnomon-secrets` and
`dockerhub-registry` secrets** (re-create them from 1.3 and 4.1 before reinstalling).
`Retain` keeps the database files in `/pipedev/k8s-local/...`. A re-created PV binds again; if a PV is stuck in `Released`,
see [Troubleshooting](#9-troubleshooting).

## 5. Verify a deployment

```sh
kubectl -n gnomon get pods,pvc,ingress,cronjob
curl -fsS http://gnomon.d2-india.com/api/v1/health/ready && echo
curl -fsSI http://gnomon.d2-india.com/ | head -3
```

- All pods `Running`/`Ready`; PVCs `Bound`.
- Sign in at http://gnomon.d2-india.com with the admin email/password from the secret
  and change the password.
- Optional backup check (names for Path B; prefix `gnomon-gnomon-` for Path A):

  ```sh
  kubectl -n gnomon create job --from=cronjob/gnomon-mongodb-backup backup-check-$(date +%s)
  kubectl -n gnomon logs -f job/<that-job-name>
  ls -lh /pipedev/k8s-local/gnomon-backups/
  ```

## 6. Backups and restore

- Schedule: daily 01:30 Asia/Kolkata; archives older than 14 days are removed.
- Files: `/pipedev/k8s-local/gnomon-backups/gnomon-YYYYmmdd-HHMMSS.archive.gz` on the node.
  They share the node's disk with the database: copy them elsewhere regularly.
- Restore (replaces the `gnomon` database's collections; take a fresh backup first).
  Use `gnomon-mongodb-0` (Path B) or `gnomon-gnomon-mongodb-0` (Path A):

  ```sh
  kubectl -n gnomon exec -i gnomon-mongodb-0 -- sh -c \
    'mongorestore --uri="mongodb://gnomonadmin:$MONGO_INITDB_ROOT_PASSWORD@localhost:27017/?authSource=admin" \
       --gzip --archive --drop --nsInclude="gnomon.*"' \
    < /pipedev/k8s-local/gnomon-backups/gnomon-<stamp>.archive.gz
  kubectl -n gnomon rollout restart deploy/gnomon-api
  ```

## 7. Switching between Helm and kubectl

Both paths use `gnomon.d2-india.com` and the same data directories, so remove one before
installing the other:

1. Take a backup (section 6) and copy it off the node.
2. Remove the current path (3.7 or 4.7). The database files stay on disk.
3. Release the old PV so the directory is not claimed twice:
   `kubectl delete pv gnomon-mongodb gnomon-mongodb-backups` (leaving Helm) or
   `kubectl delete pv gnomon-k8s-mongodb gnomon-k8s-backups` (leaving kubectl).
4. Install the other path, re-using **the same MongoDB root password** in its secret
   (only the URI host differs).

## 8. Debugging with System events

**Reporting → System events** (system administrators only) lists sign-ins, every change
(timecard, leave, regularisation, imports, admin settings), background jobs and every
failed request, newest first. Events are deleted automatically after 180 days
(`SYSTEM_EVENT_RETENTION_DAYS`).

- **A user reports an error:** server errors show a short reference, e.g.
  `(reference 1a2b3c4d)`. Paste it into the search box, set the period, and open the event
  for the error code, request, IP/browser and (for 500s) the stack trace.
- **"Why can't X do Y?":** filter by their employee code and outcome = Failure.
- **Timecard questions:** stops from another machine are labelled "Stopped workday from a
  different machine" and show both machines; sessions left open on an earlier day appear as
  `timecard.stale_session_closed`.
- **Locked out of sign-in:** five wrong passwords lock that login ID for 15 minutes
  (`LOGIN_LOCKED`, HTTP 429). It clears by itself; a successful sign-in resets the count.

Routine reads and polling are not logged, and passwords/tokens are never stored.

## 9. Troubleshooting

| Symptom                                                         | Likely cause and fix                                                                                                                                                                                                                                   |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ImagePullBackOff` / `ErrImagePull`                             | Check `kubectl -n gnomon describe pod <pod>`. Wrong `DOCKERHUB_USER`/tag (still `DOCKERHUB_USER`?), tag never pushed, missing/expired `dockerhub-registry` secret (re-create it, step 1.3), or the repository is not private-accessible to that token. |
| `docker: permission denied ... docker.sock`                     | Your user is not in the `docker` group: use `sudo` or step 1.1.                                                                                                                                                                                        |
| New code not visible after a deploy                             | A tag was reused. Push with a new tag (step 2) and deploy it; hard-refresh the browser.                                                                                                                                                                |
| API `CrashLoopBackOff`, log "Invalid environment configuration" | A secret value is missing or `ACCESS_TOKEN_SECRET`/`REFRESH_TOKEN_SECRET` is shorter than 32 characters.                                                                                                                                               |
| API not ready, log "Authentication failed"                      | `MONGODB_URI` password does not match the data directory's root user. See the warning in 1.4.                                                                                                                                                          |
| MongoDB/backup PVC `Pending`                                    | Directory missing on the node (1.4), the PV was not created (3.1 / 4.3), or a PV is `Released`: `kubectl patch pv <pv> --type json -p '[{"op":"remove","path":"/spec/claimRef/uid"}]'`.                                                                |
| Upload fails with 413                                           | File larger than the 10 MB ingress/API limit.                                                                                                                                                                                                          |
| Backup job fails                                                | `kubectl -n gnomon logs job/<job>`; usually a wrong `MONGODB_URI` or a full disk (`df -h /pipedev`).                                                                                                                                                   |
